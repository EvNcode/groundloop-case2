# GroundLoop

Операционная консоль для кейса Global Coffee × Coyote о переработке кофейного жмыха.

## Возможности

- журнал сбора с разделением измеренного и оценочного веса;
- синтетические данные для 18 точек и пилота на 6 точках;
- импорт CSV/XLSX и экспорт JSON;
- формирование маршрута и завершение сбора;
- создание прослеживаемой партии, производственный поток и выпуск;
- сценарная экономика с редактируемыми параметрами;
- внутренний паспорт партии и макет маркировки;
- запрос доступа сотрудником и назначение роли администратором;
- общее хранение пилота в Supabase Auth + PostgreSQL.

## Подключение Supabase

Проект `kofe` в EvN подключён. Применены [основная схема](supabase/schema.sql), [доступ команды](supabase/team_access.sql) и [настройка политик](supabase/team_access_policy_tuning.sql) в этом порядке. [Конфигурация](dist/supabase-config.js) содержит только publishable key. Secret/service-role key в клиентский файл не добавляйте.

Первый администратор уже назначен. Новый сотрудник регистрируется на сайте и подтверждает почту; после входа появится запрос доступа. Администратор открывает раздел «Команда» и назначает роль `operator` или `viewer`. Свой статус администратора он не может изменить через интерфейс.

Приложение требует вход, загружает общее состояние пилота из PostgreSQL и сохраняет правки с проверкой версии. При конфликте одновременных изменений работа блокируется до обновления данных. Вкладка «Команда» доступна только администраторам.

## Локальный запуск

Откройте `dist/index.html` через любой статический HTTP-сервер. Например:

```powershell
npx --yes serve dist
```

## Проверка

```powershell
npm test
node --check dist/app.js
```

Все текущие объёмы, цены и технологические коэффициенты являются синтетическими допущениями и помечены в интерфейсе.
Интеграция с API Coyote и публичный QR-паспорт потребуют данных и доступа от партнёра; текущий импорт использует CSV/XLSX.
