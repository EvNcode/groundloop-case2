# GroundLoop

Рабочий сайт: https://evncode.github.io/groundloop-case2/

GroundLoop ведёт контейнер с кофейным жмыхом от кофейни до производственной партии и продажи. Сотрудник входит по личной рабочей почте и паролю; вход по почтовой ссылке также доступен. Администратор приглашает сотрудника, назначает роль и, для бариста, точку. Сотрудник подтверждает почту и задаёт пароль. Самостоятельная регистрация в Supabase Auth закрыта. В интерфейсе нет переключения ролей.

## Рабочий процесс

1. **Бариста** взвешивает контейнер, отмечает число напитков и сам проверяет качество. Чистый контейнер появляется в очереди логиста. До вывоза автор может исправить или отменить заявку. Если заявка уже назначена в рейс, логист получает отдельное уведомление; причина отмены остаётся в журнале управления. У бариста есть карта своего филиала и архив завершённых заявок старше 24 часов.
2. **Логист** начинает собственный рейс, видит филиал, бариста и адрес вывоза, добавляет готовые контейнеры и сканирует QR при получении. Другой логист не изменяет его рейс. Вывоз можно отменить до приёмки в цехе. После разрешения браузера GPS включается при активном рейсе и сохраняет координаты в базе. На карте видны точки, положение водителя и маршрут по дорогам.
3. **Производство** сканирует тот же код при приёмке. Оператор может отменить ошибочную приёмку до формирования партии. Партия создаётся после закрытия рейса. Затем фиксируются вес после сушки, пригодный вес и фактический выпуск. При доставке готового продукта оператор показывает QR выдачи логисту.
4. **Управление** видит операции, карту и журнал с фильтром отмен, оформляет заявку на продукт из готовой партии. Доступны самовывоз или доставка логистом. Для доставки указывается адрес и точка на карте. Выпуск резервируется при создании заявки, а выручка считается после фактической передачи. Администратор приглашает сотрудников, меняет роли и точки, отключает доступ. Сервер не позволяет продать больше выпущенного.

События передаются через Supabase Realtime с резервным обновлением каждые 20 секунд. Все переходы, принадлежность записи сотруднику, сканы и остаток проверяются триггерами и RLS в Postgres. Управление не утверждает записи бариста: оценку качества делает бариста на точке.

## Доступ и запуск

- В Supabase Auth Site URL и разрешённый адрес возврата настроены на `https://evncode.github.io/groundloop-case2/`. Email включён, подтверждение почты обязательно, анонимный вход и самостоятельная регистрация выключены. Почтовый вход использует `shouldCreateUser: false`.
- Первый администратор: `hairullanurlybakyt@gmail.com`. Только он управляет командой и отправляет приглашения через серверную Edge Function `groundloop-invite`. В ней повторно проверяется действующая Auth-сессия и право администратора. Для нового сотрудника ссылка из письма открывает экран установки пароля.
- Для показа созданы отдельные аккаунты двух бариста, двух логистов, одного оператора производства и двух руководителей. Их пароли не хранятся в репозитории. Обычные руководители видят операции и продажи, но не управляют доступом команды.
- Рабочий набор ограничен шестью филиалами Global Coffee в Шымкенте. Их адреса и координаты здания сверены с карточками Яндекс Карт; точное место входа/погрузки нужно подтвердить с сетью перед реальными рейсами. Адрес производственного цеха пока не сообщён, поэтому цех не нанесён на карту.
- Карточки точек: [Тауке хана, 62](https://yandex.kz/maps/ru/org/global_coffee/70404728667/), [Мамытова, 58/1](https://yandex.kz/maps/ru/org/global_coffee/78441015292/), [Гани Иляева, 23](https://yandex.kz/maps/ru/org/global_coffee/15146228727/), [Рыскулова, 10/2](https://yandex.kz/maps/ru/org/global_coffee/38185304619/), [Момышулы, 109/2](https://yandex.kz/maps/ru/org/global_coffee/134661025037/), [Дулати, 202](https://yandex.kz/maps/org/231211279936/).
- Для сканирования нужен доступ браузера к камере. При недоступной камере можно ввести код с этикетки. GPS включается логистом на телефоне и требует разрешения геолокации; без него остальные функции работают.
- Работа с Coyote POS пока не подключена: данные о контейнере вводит бариста, а рабочую почту приглашает администратор GroundLoop. Для единого входа через Coyote потребуется его SSO/OIDC или иной официальный способ проверки сотрудников. Для автоматической загрузки понадобятся API или отчёт Coyote с точкой, временем, числом напитков и весом, если вес там измеряется. GPS использует Geolocation API браузера. Карта показывает уличный слой Esri по умолчанию и переключается на спутниковый слой Esri; источники указаны в обязательной атрибуции карты. Слои ArcGIS MapServer доступны без ключа, но относятся к старому API и могут быть отключены: для долгосрочной эксплуатации нужен договорный ключ актуального сервиса. Дорожный маршрут пока рассчитывает публичный OSRM demo API; его текущий вызов передаёт координаты остановок этому сервису. Для рабочего внедрения нужен договорный маршрутизатор или собственный сервер.

Локально:

```powershell
npm ci
npm run build
npm test
python -m http.server 8789 --directory dist
```

SQL миграции находятся в `supabase/migrations/`. `tests/workflow.sql` проверяет весь путь в транзакции с откатом. GitHub Actions собирает и публикует `dist/` на GitHub Pages после push в `main`. В клиенте находится только Supabase publishable key; серверных секретов нет.

## Границы результата

В операционной базе есть проверочные записи сотрудников, контейнеров, рейсов, партий и передач продукта. Они нужны для показа процесса и не являются фактическими замерами сети. Старые учебные записи хранятся отдельно и в показатели нового сайта не попадают. Физический образец подставок, замеры выхода материала и проверка себестоимости на реальных объёмах требуются для окончательной защиты кейса 2.
