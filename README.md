# GroundLoop

Рабочий сайт: https://evncode.github.io/groundloop-case2/

GroundLoop ведёт контейнер с кофейным жмыхом от кофейни до производственной партии и продажи. Сотрудник входит по ссылке на рабочую почту. Его роль и точка задаются руководителем. В интерфейсе нет переключения ролей.

## Рабочий процесс

1. **Бариста** взвешивает контейнер, отмечает число напитков, сам проверяет качество и записывает замечания. Чистый контейнер появляется в очереди логиста. Сомнительный остаётся на точке. До вывоза автор может исправить или отменить запись; отмена сохраняется в журнале.
2. **Логист** начинает рейс, добавляет готовые контейнеры и сканирует QR-код при получении. Вывоз можно отменить до приёмки в цехе. При разрешении телефона GPS координаты рейса обновляются в базе; руководство видит положение и время последнего сигнала.
3. **Производство** сканирует тот же код при приёмке. Оператор может отменить ошибочную приёмку до формирования партии. Из принятых контейнеров создаётся партия, фиксируются вес после сушки, пригодный вес и фактический выпуск.
4. **Управление** добавляет и обновляет точки, назначает сотрудникам роль и точку, видит операции и GPS рейсов, записывает продажи готовых упаковок. Сервер не позволяет продать больше выпущенного.

События передаются через Supabase Realtime с резервным обновлением каждые 20 секунд. Все переходы, принадлежность записи сотруднику, сканы и остаток проверяются триггерами и RLS в Postgres. Управление не утверждает записи бариста: оценку качества делает бариста на точке.

## Доступ и запуск

- В Supabase Auth разрешите адрес возврата `https://evncode.github.io/groundloop-case2/` и задайте его как Site URL. Иначе письмо может вернуть сотрудника на другой сайт.
- Первый руководитель: `hairullanurlybakyt@gmail.com`. После входа в разделе «Команда» добавьте рабочие адреса сотрудников и назначьте роли. Сотрудники входят по ссылке из письма, пароль не требуется.
- Для сканирования нужен доступ браузера к камере. При недоступной камере можно ввести код с этикетки. GPS включается логистом на телефоне и требует разрешения геолокации; без него остальные функции работают.
- Работа с Coyote POS пока не подключена: данные о контейнере вводит бариста. Для автоматической загрузки понадобятся API или отчёт Coyote с точкой, временем, числом напитков и весом, если вес там измеряется. Для карты маршрута с расчётом времени понадобятся адреса/координаты точек и маршрутизатор. Текущий GPS использует встроенный Geolocation API браузера, карта — OpenStreetMap.

Локально:

```powershell
npm ci
npm run build
npm test
python -m http.server 8789 --directory dist
```

SQL миграции находятся в `supabase/migrations/`. `tests/workflow.sql` проверяет весь путь в транзакции с откатом. GitHub Actions собирает и публикует `dist/` на GitHub Pages после push в `main`. В клиенте находится только Supabase publishable key; серверных секретов нет.

## Границы результата

Операционные записи нового сайта начинаются с пустой базы. Старые демонстрационные записи хранятся отдельно и в рабочие показатели не попадают. Цифровой процесс работает, но физический образец подставок, замеры выхода материала и проверка себестоимости на реальных объёмах требуются для окончательной защиты кейса 2.
